## A. Томьёонууд

```
Target Months      = Target Days / 30                         (§3)
Recommended Stock  = Average Monthly Sales × Target Months     (§5)
Current Stock Days = (Current Stock / Avg Monthly Sales) × 30  (§7)
                     ⚠️ Avg = 0 → 0, төлөв = Хөдөлгөөнгүй
Shortage           = MAX(Recommended − Current, 0)             (§8)
Excess             = MAX(Current − Recommended, 0)             (§9)
Transfer Qty       = CEILING(MIN(дутагдал, илүүдэл))           (§12)
                     ⚠️ эх үүсвэрийн илүүдлээс ХЭТРЭХГҮЙ
New Purchase       = CEILING(Recommended − Current − TransferIn), <= 0 бол 0  (§13)
```

`Average Monthly Sales` нь **байршил тус бүрээр** (SKU × байршил), lookback
нийлбэрийг **бүтэн саруудын тоонд** хуваасан. ABC/XYZ нь SKU түвшний
(Phase 3), байршлаас хамаарахгүй; `targetDays` нь
`InventoryPolicy(locationType, abc, xyz)`-оос ирнэ.

### Хоёр дүрэм зөрчилдөх үеийн шийдэл

§10 (CEILING) ба §12 (эх үүсвэрээс хэтрэхгүй) зөрчилдвөл **физик хязгаар
давамгайлна**: илүүдэл 100.4, дутагдал 300 бол `CEILING(100.4) = 101` нь
илүүдлээс давах тул **100** (FLOOR) болно. Байхгүй барааг шилжүүлэх боломжгүй.

## B. Тохиргоо (§2, §11)

Бүх утга DB / JSON-оос — hardcode **байхгүй**:

| Юу | Хаана |
|---|---|
| Target days матриц (2 × 3 × 3 = 18) | `inventory_policy` хүснэгт ← `analysis-defaults.json` |
| daysPerMonth = 30 | `inventory-status-rules.json` → `params` |
| Нөөц дуусах хязгаар = 7 хоног | `params.stockoutDaysThreshold` |
| Хэт их коэффициент = 1.5 | `params.overstockFactor` |
| Төлөвийн дүрэм + **дараалал** | `inventory-status-rules.json` → `statuses` |
| Шийдвэрийн дүрэм + **дараалал** | `inventory-status-rules.json` → `decisions` |

`InventoryPolicy` олдохгүй бол **алдаа шиднэ** — чимээгүй default руу унахгүй
(буруу зорилтот хоног нь буруу шийдвэр гаргуулна).

⚠️ **Тодруулга:** дараалал ба параметрүүд бүрэн тохируулагдана; нөхцөлийн
*хэлбэр* (`condition.type`) нь кодод нэрлэгдсэн предикат (дурын илэрхийлэл биш).
Энэ нь аюулгүй байдал болон тестлэгдэх чадварын үүднээс сонгосон шийдэл.

### Төлөвийн дараалал (эхний таарсан нь ялна)

| # | Төлөв | Нөхцөл |
|---|---|---|
| 1 | Хөдөлгөөнгүй | avg = 0 |
| 2 | Нөөц дуусах эрсдэлтэй | stockDays ≤ 7 |
| 3 | Хэт их нөөцтэй | stockDays > target × 1.5 |
| 4 | Удаан эргэлттэй | XYZ = Z **ба** stockDays > target |
| 5 | Нөөц багассан | stockDays < target **ба** > 7 |
| 6 | Зохистой | target ≤ stockDays ≤ target × 1.5 |

**Илэрсэн хилийн зөрчил:** `target ≤ 7` байх ангилалд (CZ эмийн сан = 7 хоног)
дүрэм 2 нь дүрэм 6-г **дарж түрүүлнэ** — 7 хоногийн нөөцтэй CZ бараа
"Зохистой" биш "Нөөц дуусах эрсдэлтэй" болно. Эмийн салбарт 7 хоног бодитоор
нимгэн тул зориудаар ийм дараалалтай үлдээв, JSON-д тайлбарласан. Тохиромжгүй
бол `stockoutDaysThreshold`-ыг бууруулна.

### Шийдвэрийн дараалал

1. **PROMOTION** — avg = 0 **ба** үлдэгдэлтэй
2. **STOP_PURCHASE** — төлөв нь Хэт их нөөцтэй / Удаан эргэлттэй (§14)
3. **TRANSFER** — шилжүүлэг хүлээн авна
4. **NEW_PURCHASE** — шилжүүлгээр хаагдаагүй дутагдал үлдсэн
5. **MONITOR** — арга хэмжээ шаардлагагүй

⚠️ **PROMOTION-ы нөхцөл шаардлагад ЗААГДААГҮЙ.** Одоогийн default
(борлуулалтгүй атлаа үлдэгдэлтэй) нь миний санал — **бизнестэй тохирох
шаардлагатай**. JSON-д тэмдэглэсэн.
